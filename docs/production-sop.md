## 一、開新作品的共同流程

1. `output/<類型>/<作品名>/` 建資料夾（類型如 `歌曲MV`，作品名用中文標題；沒有歌的程式影片到 `media-code-video` 做），至少放一份 `製作紀錄.md`（沒有製作紀錄的作品等於沒做）。
2. `製作紀錄.md` 一開始就要有三個區塊：**使用者的決定**（定案就不再問第二次）、**進度表**、**定稿清單**（檔名＋規格＋路徑）。
3. 生成的檔案產出後**從 ComfyUI 的 output 資料夾搬到作品的 `work/`**，分 `audio/`、`image/`、`video/`；程式動畫專案也放 `work/` 底下。
   使用者確認定案後，才把成品移到作品資料夾最上層、改名 `<作品名>.mp4`（社群壓縮版 `<作品名>_社群版.mp4`、720p `<作品名>_手機版.mp4`、歌曲 `<作品名>.mp3`）；舊版本的原始專案移到 `舊版/`。`製作紀錄.md` 記定稿檔路徑。
4. 工作流程 JSON 存進 `work/workflows/`。
   舊作品沒留檔時，**從輸出檔內嵌的 metadata 取回**（mp4／mp3 的 `format_tags.prompt`、PNG 的 `prompt` 區塊），不要憑記憶重寫。
5. 實測出來的**通用**經驗寫回 `comfyui` 技能；只有這件作品專屬的設定與決定留在 `製作紀錄.md`。
   寫回技能時情境用通稱（例如「古裝庭院雙人短片」），**使用者的照片、聲音、完整提示詞不得進公開 repo**。

### 一首歌有多版 MV 時的資料夾（2026-11-03 定案）

同一首歌有兩版以上 MV（不同畫風，或封面圖配歌曲的社群短片）時，**每版開一個子資料夾**；只有一版 MV 的歌照上面的結構，不開子資料夾。範例：`output/歌曲MV/衝破這片天/`。

```
<作品名>/
├── <作品名>.mp3、歌詞.txt、製作紀錄.md、主腳本   只放各版共用的歌曲成品
├── work/                audio/、workflows/、analysis/（節拍）等各版共用的工作檔
├── MV-<畫風>/           一版一個，例如 MV-各行各業/、MV-水墨一筆/、MV-社群/
│   ├── <作品名>_<畫風>.mp4、_社群版.mp4、_手機版.mp4、_歌詞字幕.srt   定案後才放這層
│   ├── cover_<畫風>.png、cover_<畫風>_9x16.png、cover_<畫風>_4x5.png
│   ├── 製作紀錄.md、發布資訊.md
│   └── work/            原始專案（src/、tools/、index.html）、未定案成品放 work/video/、
│                        只有這一版用到的素材（剪輯音檔、封面原圖、工作流程）
└── 舊版/                不採用的試作，例如 舊版/MV-試作/
```

- **判斷放哪一層**：被兩版以上用到的才放歌曲那一層；只屬於某一版的，包括封面（取自該版畫面）、發布資訊、該版專用的剪輯與工作流程，都放進該版的子資料夾。
- **檔名加畫風後綴**：`<作品名>_<畫風>.mp4`、`cover_<畫風>.png`，讓檔案下載或傳出去之後還分得出是哪一版。檔名本來就分得出來的可保留（例如 `衝破這片天_直式60秒_社群版.mp4`）。
- **製作紀錄一版一份**：歌曲的 `製作紀錄.md` 只記歌曲本身，開頭列各版索引（版本、資料夾連結、狀態）；各版的經過、分鏡、使用者決定寫在該版的 `製作紀錄.md`。
- **原始專案攤平在該版的 `work/`**：`work/` 直接放 `src/`、`tools/`、`index.html`，不再多包一層 `mv/`。這樣它跟歌曲資料夾的相對深度固定，`../../<作品名>.mp3`、`../../work/audio/` 這類路徑在各版都能用。
  算圖在該版的 `work/` 底下跑：`--audio ../../work/audio/<歌>.flac --out video/<檔名>.mp4`。
- **第二版出現時才分版**：原本只有一版的歌，要做第二版時先把第一版搬進 `MV-<畫風>/`，並改檔名、拆製作紀錄、修路徑，再開新版。
- **搬移前後要驗**：先等雲端同步完成；搬完比對檔案數與大小，再用 grep 找出製作紀錄、發布資訊、README、程式註解裡的舊路徑，全部改掉。

## 三、音樂＋封面

1. Music 3 生歌（範本 `audio_minimax_music_3`），一版一版改，**每版只動一個變數**才對照得出來
   （《衝破這片天》第 2 版刻意只改風格、不動歌詞與 seed）。
2. 使用者試聽選版。
3. 封面用 Z-Image Turbo 生，提示詞寫明「畫面中沒有任何文字」，要疊字的區域刻意留暗、留乾淨。
4. 合成發布用影片（封面＋音軌）時，**ffmpeg 參數要記進 `製作紀錄.md`**。
   ——《衝破這片天》的 FB 版當時沒留紀錄，現在補不回來了，不要再犯。

⚠️ **mp3 內嵌的 metadata 含歌詞全文**，比影片更敏感。

## 四、發布前檢查清單（硬規則）

作品驗收通過後，照 [發布資訊範本](../templates/發布資訊範本.md) 建立 `output/<類型>/<作品名>/發布資訊.md`，填寫 YouTube／Facebook／Instagram／Threads 文案、AI 揭露與實際工具名單。需要上傳的檔案以 `製作紀錄.md` 定稿清單中的分享版為準；發布後把公開網址記回該文件。

> 使用者說要發布（社群、傳給別人）時**主動提醒一次**，同意後才做。
> **一律另存新檔，ComfyUI 的原始輸出不動。**

三種產出物內嵌的位置不同，清法也不同：

| 格式 | 內嵌在哪 | 清除指令 |
|---|---|---|
| mp4 | 容器 metadata 的 `prompt` | `ffmpeg -i in.mp4 -map_metadata -1 -c copy out.mp4` |
| mp3 | 容器 metadata 的 `prompt`（**含歌詞全文**） | `ffmpeg -i in.mp3 -map_metadata -1 -c copy out.mp3` |
| PNG | `tEXt` 區塊的 `prompt` | Pillow 重存一份不帶 `info`（見下） |

PNG：
```bash
python -c "from PIL import Image; Image.open('in.png').save('out.png')"
```

### 驗證：兩道都要過

`AGENTS.md` 要求 `ffprobe` **＋位元組掃描**雙重驗證，缺一不可——ffprobe 只看得到容器層的標準欄位。

**第一道**（mp4／mp3）：只剩 `major_brand`、`encoder` 之類，沒有 `prompt`：
```bash
ffprobe -v error -show_entries format_tags -of json out.mp4
```

**第二道**（三種格式通用）：掃檔案位元組，**必須是 0**：
```bash
grep -ac 'prompt\|safetensors\|class_type' out.mp4
```

> `grep -c` 數的是「符合的行數」，不是出現次數——所以只有 **0 = 乾淨** 有意義，非 0 一律當成有殘留、回去重清。
> ComfyUI 寫的 metadata 一定是 JSON，key 都是 ASCII，掃這三個關鍵字就夠。
> 上面整套（造髒檔 → 清 → 雙重驗證）在 2026-09-20 用 ffmpeg 8.1.2 ＋ Pillow 12.3.0 實測通過。

### ⚠️ 已知未清的檔案

ComfyUI 的**原始輸出段落仍帶完整工作流程**。目前確認過還沒清、單獨傳出去前要先處理的：

- 下載資料夾的 `臭豆腐_02_黑熊問答.mp4`、`臭豆腐_04_哈氣倒地.mp4`

## 五、跨作品已定案的決策

只記**結論**，理由與完整踩坑過程在 Obsidian（`media-music-video/專案工作流程.md`）。

H3 影片（Ref2VA、首尾幀、定妝、加速 LoRA、參考影片等）的定案已隨短片移到 `media-short-film/docs/03_規則與踩坑.md`，這裡不再列。
之後有新的（例如封面）再加在這一節。

### 歌曲：哪種歌用哪條路（2026-10-28 定案）

- **原創新歌**（只給歌詞或主題，旋律交給 AI）：ComfyUI Music 3，照第三節。
- **照譜、照詞唱**（使用者給了譜，旋律一個音都不能改）：**不用 ComfyUI**（YuE2、ACE-Step 試過 10 輪：YuE2 確定會唱成粵語；兩者能否逐音照譜都未確定）。
  人聲用 OpenUtau＋DiffSinger 國語聲庫照 MIDI 唱，伴奏用 `tools/sing/` 照同一份譜寫 MIDI、FluidSynth 算真樂器，numpy 混音。
  流程見 [照譜唱歌曲流程](照譜唱歌曲流程.md)。
- 國語歌詞的讀音以**台灣讀音**為準，打譜時拼音逐字標聲調，破音字列給使用者核對。

### 歌詞 MV：逐字時間（2026-11-01 定案）

- 維持 **Whisper 取逐字時間＋起音分析**：由 agent 挑起音、改時間，使用者試聽後指出哪裡不準，agent 再修。
- 不用 Qwen3-ForcedAligner 強制對齊：〈把光留給我〉〈衝破這片天〉實測後，使用者試聽判定現有時間較準。
- 唯一例外是〈衝破這片天〉「我不怕 不怕墜落」：Whisper 字數對不上、句內改用平均分配，起音也挑早約 2 秒，字幕太早出現。
  **字數對不上而改平均分配的句子，一律由 agent 重新核對起音**，並標給使用者重點試聽。
- **核對起音看人聲分軌的音量包絡**（htdemucs 分軌）：一段漸強的長音和一串短促的起音，代表的字位置可能完全不同
  （〈衝破這片天〉「我不怕」92.0–93.1 秒是長音，七個字其實都在 93.78–95.22 秒，字幕因此延後約 1.5 秒）。只看包絡判斷的地方，標給使用者試聽。
- **同一首歌的多版 MV 共用一份逐字時間**：放歌曲的 `work/lyrics-data.js`，各版 `index.html` 用 `../../work/lyrics-data.js` 載入，
  不要各版複製一份（改一次時間就要同步好幾份 JS 與 SRT，容易漏）。改完時間，重產每一版的 SRT。已定案的版本可以保留自己的舊份，不跟著改。

### 歌詞 MV：節拍分析（2026-11-01 定案）

- 新 MV 用 `tools/mv/listen.py` 取**拍點與小節**，不再用各作品自寫的 `analyze_audio.py`：兩首歌實測，舊工具的 BPM 都不符合鼓軌（125→94.55、86.39→74.80）。
- 它的**段落標籤與逐字時間不採用**：〈衝破這片天〉的副歌曾被標成主歌，段落由 agent 對照歌詞判斷。
- 環境：獨立虛擬環境，裝 `scipy matplotlib demucs torch torchaudio torchcodec`（demucs 需要 torch），不用 ComfyUI 的環境。分軌結果是中間檔，放本機暫存資料夾。
- 流程：先分軌，再分析。`--lrc` 給帶時間的歌詞能幫助判斷小節頭；輸出放作品的 `work/analysis/`（節拍屬於歌曲，同一首歌的各版 MV 共用），`audio.wav` 不留在雲端硬碟。

```bash
python -I -X utf8 -m demucs -n htdemucs -o <暫存資料夾> <歌.mp3>
```

```bash
python -I -X utf8 tools/mv/listen.py <歌.mp3> --stems <暫存資料夾>/htdemucs/<歌名> --lrc <歌詞.lrc> --out <輸出資料夾>
```

### 歌詞 MV：逐句分鏡（2026-11-01 定案）

動手畫之前，分鏡表每一句都要有這三欄（方法參考 mv-director，MIT；只取方法，未使用其程式）：

- **字面**：這句在說什麼。
- **畫面**：看得到什麼（誰、在哪、在做什麼、鏡頭）。
- **關鍵詞**：要演出來的原詞 1–3 個，唱到該詞時畫面要有變化。

驗收方式：只看「畫面」欄，沒聽過這首歌的人也要猜得出歌詞大意。重複的句子要升級，不原樣再放一次。

### 程式算圖：平行程序數（2026-11-02 定案）

- 無頭瀏覽器逐格算 1080p 時，**32 GB RAM 的電腦最多開 6 個程序**（`--workers 6`）。實測 12 個會把記憶體用到 96%，整台電腦卡頓，算圖速度也變慢。
- **成品先寫本機暫存資料夾，算完再搬進雲端硬碟**：直接寫進雲端資料夾，雲端硬碟會一邊算一邊同步還沒寫完的大檔（1080p CRF 17 全曲可達 650 MB）。
- **一筆一筆累積的畫面也能分段平行算**（水墨一筆、沙畫這類「只加不擦」的畫法）：每個分段開始輸出前，先把該時間點之前的所有筆畫補畫一遍；
  隨機數一律固定 seed，分段算出來的畫面才會跟一次算到底的一樣。`render.mjs --stills` 跳時間抽格也靠這個。
- **時間軸建好先檢查**：每個動作的時間都不是 `NaN`、排序正確。從拍點陣列取時間時，索引超出範圍會得到 `NaN`，整條時間軸排序全壞，後面的動作都不跑，畫面卻不會報錯。
- **改程式結構（不改畫面）後，用抽格逐位元組比對驗證**：改之前先用 `--stills` 抽 5–6 格（挑有字幕、有動作的時間），改完再抽同樣的時間，PNG 逐位元組相同才算沒改到畫面。

### 試片與驗收紀錄（2026-11-03 定案）

- **試片固定選同一段**：第一次副歌、畫面變化最多的 15 秒左右（〈衝破這片天〉是 50.6–66.12 秒）。同一首歌換畫風時用同一段，各版才能並排比較。
- **新畫風另開一版專案**（`MV-<畫風>/`，見第一節），不覆蓋已完成的版本；使用者試過後撤回的做法（疊色、簡化筆畫等）寫進該版製作紀錄的「使用者的決定」。
- **每次算完全曲，製作紀錄用同一個格式記驗收**：
  - 抽幾格目視
  - 黑畫面只出現在結尾淡出
  - 沒有 5 秒以上的凍結
  - 音軌全長、零延遲，與原曲相關係數 ≥ 0.999
  - `format_tags` 與位元組掃描沒有 `prompt`
  - 已知小缺點（列出來，下一輪修或請使用者決定）

### 動畫／歌詞 MV 的畫面規則（使用者定案）

不管畫面是程式畫的還是生圖合成的，都是驗收條件。出處：〈衝破這片天〉MV 的多輪指正（2026-09 各行各業版；2026-11 流場筆觸、水墨一筆、沙畫三版），〈把光留給我〉MV 沿用。

**字幕**

- 放在畫面下方、字不要太大（1080p 主歌約 54px、副歌約 60px），同一時間只顯示一層。
- **KTV 效果**：唱到哪裡，字就由左到右變色；長音掃得慢。
- 歌詞逐字照使用者給的歌詞檔，一個字都不改（含標點、全形空白、引號）；段落標記與括號說明不是唱詞。
- **SRT 檔名不可與影片同名**：同名時播放器會自動載入，燒進畫面的字幕上又疊一層，看起來像雙層字幕。
- 每句顯示到「這句的 `end`」和「最後一個字唱完，但不超過下一句開始」兩者較晚的那個時間：`max(L.end, min(最後一字結束, 下一句 start))`。同一時間只顯示一句。
- **片名、片尾字**：畫風本身寫不出細字時（例如沙畫），改用字型（標楷）疊在畫面上，並加描邊，畫面暗處和亮處都要看得清楚。

**人物與物件**

- **坐著的人一定要有椅子**，腳要著地；椅子大小依人物身高。
- 桌子高度依身高：坐姿桌面約在髖部上方 0.12 個身高，站立的工作台約在腰（髖部）的高度；電腦之類的東西放桌上，不放地上。
- **手要碰到該碰的東西**（筆、把手、鍋柄、門把、別人的手……），工具要握在手上。
- **手不可以往身後反折**；舉手、揮手、歡呼都往前上方舉。
- **朝向**：教室裡的學生**背對鏡頭、面向黑板**（這樣才看得到黑板正面）；其他場景的人也要面向他們在看的東西。
- 人物比例合理（大人約小孩的 1.5–1.7 倍）；物件要像實物（籃框有籃板與籃網、桌子四隻腳、終點線不會多一根桿子）。
- **剪影人物要整個實心、連成一體**，頭和脖子不可以分開畫。
- **姿勢不要左右鏡像**（太死板），要自然；兩隻手臂粗細一致。
- **多人的場景每個人都不一樣**：動作、高矮、站位、朝向、外型（大人或小孩、髮型、帽子、裙子、胖瘦）都分開，舉手也有先有後。
- **剪影輪廓要一看就知道是什麼**。被指正過的：背上被風吹起的衣襬像包袱、手臂併進身體像一根錐子、兩手平行往前舉像拿槍、小人物太胖太矮。
- **象徵性的東西照原本的尺度演**：眼淚從眼角一顆顆滑下來再滴落，不要滿畫面落下（看起來像下雨）。
- **畫面裡的東西不要互相碰到**（例如月亮碰到樹梢），出片前抽格檢查。

**動作**

- **不要危險動作**（被換掉過的：站在梯子頂端、颱風天撐傘）。
- 動作合理、速度不要太快：攀爬要一步步爬，安全掛鉤由手移動、不會自己跑；跳高用剪式；批改是一手按紙、一手打勾。
- 物品不會自己移動，放好的東西不會突然消失（循環動畫不要用取餘數把累積的東西歸零）。

**畫面變化與筆觸**

- **前奏、間奏也要分幕**，不要一個畫面撐十幾秒（被指正過：9–20 秒一直是同一組漩渦、前奏雲太淡幾乎沒動）。**5 秒以上畫面沒有變化就要修**。
- **手繪類畫風的筆觸不要太工整**：圓不會很圓、線不會很直、力道時輕時重；月亮、流星、樹枝都照手畫的樣子。

**流程**

- 先出計畫或分鏡給使用者看，再動手；先做一個基準場景＋10–15 秒試片確認風格，再做全曲。
- 出片前全片掃一次（骨架動畫用檢查工具每 0.25 秒掃「手腳構不到／手臂反折／坐姿」，生圖則逐張目視），上面每一條都要過；
  另外檢查黑畫面／凍結、音軌與原曲零延遲且全長，再做第四節的 metadata 雙重驗證；紀錄格式見上方〈試片與驗收紀錄〉。
- 字幕有沒有對到歌聲由使用者試聽確認（agent 聽不到）。
