# 發布資訊範本（YouTube／Facebook／Instagram）

> 用法：作品驗收通過後，把本檔複製成 `output/<slug>/發布資訊.md`，依作品內容替換 `<…>`，刪掉用不到的區塊。
> 適用短片、歌曲、歌詞 MV、動畫、圖片；公開文案只保留可直接貼上的內容，內部檔案與查核紀錄放第 4、5 節。
> 平台的字數、hashtag、影片規格與 AI 標示要求會變，實際發布前再到平台官方說明與上傳畫面確認；本檔不把舊版平台數字當作固定規則。

## 0. 各平台共用資訊

### 作品資料（內部填寫，不直接貼出去）

| 項目 | 內容 |
|---|---|
| 作品名稱 | 〈<作品名>〉 |
| 形式 | <短片／歌曲／歌詞 MV／動畫／圖片> |
| 主題與對象 | <一句話主題、希望誰看到> |
| 定稿依據 | `notes.md` 的定稿清單；<版本> |
| 發布用檔案 | `media/<audio／video／image>/<已清 metadata 的檔名>` |
| 規格 | <時長、尺寸、畫面比例；音訊作品填格式與取樣率> |
| 預計平台 | <YouTube／Facebook／Instagram> |
| 發布狀態 | <文案草稿／待使用者驗收／可上傳／已發布> |

### AI 揭露（各平台文案都要有）

照實際製作方式填寫，區分歌曲、人聲、圖片與動畫。生圖加程式動畫的 MV 應分別列出兩種做法；全程式作品寫明程式建模、動畫或合成配樂。

```text
🤖 AI 與製作方式揭露
<本作品的哪些部分由 AI 生成、哪些部分由程式或人工製作。>
<有克隆真人聲音時：〇〇的聲音以本人錄音、經本人授權克隆。>
<有改作或引用時：本作品參考／改作自〈原作名〉，來源與授權說明如下。>
```

可依實際做法選用：

- 歌曲：「本歌曲的人聲與音樂由 MiniMax-Music3 生成。」
- 生圖加動畫 MV：「歌曲由 MiniMax-Music3 生成；插畫由 OpenAI 生圖（Codex）製作，動畫、運鏡與歌詞字幕以程式合成。」
- 生成短片：「畫面與聲音由 MiniMax H3 生成，經人工挑選與剪接。」
- 全程式動畫：「本作品以 Blender／Canvas 製作動畫，配樂以程式合成，製作過程由 AI 協助撰寫程式。」

### 使用的 AI 與工具（照實際用到的填）

工具名單以該作品的 `notes.md`、生成腳本與工作流程為依據；需要查舊模型時，從原始輸出的 metadata 取回。無法確認的型號不要猜。

```text
🛠 使用的 AI 與工具
<工具／模型名（實際用途）>｜<工具／模型名（實際用途）>｜<協作工具>
```

常用名稱範例，僅保留確實使用的項目：

| 用途 | 可填名稱 |
|---|---|
| 歌曲、人聲與配樂生成 | MiniMax-Music3 |
| 影片與聲音生成 | MiniMax H3 |
| 插畫、封面、圖像編修 | OpenAI 生圖（Codex）／Qwen Image Edit／Z-Image Turbo |
| 3D 建模與動畫 | Blender |
| 程式動畫 | Canvas 2D／HyperFrames／GSAP／Three.js |
| 音訊合成 | Python／NumPy |
| 本機生成工作流 | ComfyUI |
| 剪接、合成與字幕 | FFmpeg／Python／<實際剪輯工具> |
| 製作協作 | Codex／Claude Code／<實際協作工具> |

### 原作與素材來源（有引用、改作或外部素材才保留）

```text
🎞 原作與素材來源
〈<原作／素材標題>〉，<作者／頻道>：<公開網址>
<授權或使用依據；需要署名時照來源要求填寫。>
```

## 1. YouTube

### 標題（提供 3–5 個候選，再選一個）

1. 〈<作品名>〉｜<主打句>｜<AI 原創歌曲／歌詞 MV／AI 短片／動畫作品>
2. <對目標觀眾喊話的候選>
3. <作品金句或情境式候選>

主題與作品特色放前面；短劇的反轉保留在影片裡。封面文字與標題互相呼應。

### 搜尋標籤（Studio 的「標籤」欄）

```text
<作品名>, <主題詞>, <曲風或類型>, <角色名>, 繁體中文, <實際使用的生成模型>
```

### 上傳時確認

- 封面使用已確認的畫面，文字與主體在預覽中清楚可辨。
- 有上傳字幕時，使用核對過的繁體中文字幕；歌詞 MV 另確認燒錄字幕與外掛字幕的顯示效果。
- 依作品內容確認「兒童專屬內容」及「變造或合成內容」設定。
- 章節時間、標題／說明字數、hashtag 與上傳規格，以當下的官方說明及 Studio 提示為準。
- Shorts 另檢查直式構圖、字幕及主體安全區；需要重做版型時另存版本。

## 2. Facebook（貼文／Reels）

```text
<第一行主打句：作品最想傳達的一句話。>

<補 1–3 行情境、心意或創作想法。>
<一個自然的互動提問>

🤖 <一句話 AI 與製作方式揭露>
🛠 <確認過的工具名單，一行>
<有引用時：🎞 原作／素材：〈原作名〉<作者> <公開網址>>

#<作品類型> #<主題> #<系列名>
```

- hashtag 以少量、與作品直接相關的詞為主；沒有公開連結就刪掉連結佔位。
- 歌曲搭配封面或 MV 上傳時，寫清楚是哪首歌、哪個版本。
- 依實際內容及發布畫面確認 Meta 的「AI 資訊」揭露設定。
- 上傳前預覽封面、畫面比例、字幕與音量。

## 3. Instagram（Reels／貼文／輪播）

```text
<第一行吸睛句或作品金句>

<1–2 行情境或創作想法>
<一個互動提問>

🤖 <一句話 AI 與製作方式揭露>
🛠 <確認過的工具名單，一行>
<有引用時：🎞 原作／素材：〈原作名〉@<作者帳號>>
<確實已放連結時：完整作品連結見個人檔案／限時動態。>

#<作品類型> #<主題> #<系列名>
```

- hashtag 數量、說明字數、影片規格及 AI 揭露，依當下官方說明與發布畫面確認。
- Reels 另確認直式畫面、封面裁切及動態牆預覽；圖片或輪播逐張確認文字與裁切。
- 完整歌詞太長時，內文選一段並連到確實存在的完整作品頁。

## 4. 內部來源與授權紀錄（不貼出去）

依這件作品實際用到的模型、照片、聲音、音樂及外部素材填寫；模型規則回查 `comfyui` 技能與原始授權，不套用其他專案的模型名單。

| 項目 | 使用來源／版本 | 授權或同意依據 | 查核日期與狀態 |
|---|---|---|---|
| 模型與工具 | <名稱、版本> | <官方授權連結；需要的公開署名> | <日期／待確認或已確認> |
| 外部素材或改作來源 | <公開來源網址> | <授權或同意紀錄的位置> | <日期／狀態> |
| 真人照片／聲音 | <內部紀錄代號> | <本人同意的使用範圍> | <日期／狀態> |

私人照片、參考聲音、完整提示詞、本機絕對路徑與金鑰不放進公開文案。對外只放必要的署名、揭露與公開來源。

## 5. 發布前檢查（內部用）

- [ ] 使用者已完成適用的觀看／試聽驗收，發布版本與 `notes.md` 的定稿清單一致。
- [ ] 發布用檔案在 `output/<slug>/media/`，原始輸出保留，分享版另存新檔。
- [ ] 已照專案根目錄的 `docs/production-sop.md` 第四節清除分享版 metadata，並完成容器／PNG 欄位及位元組掃描雙重驗證。
- [ ] AI 揭露與工具名單符合實際工作流程；有片尾名單時兩者一致。
- [ ] 外部素材、改作、真人照片與聲音的使用依據已確認，需要的公開署名已填入。
- [ ] 影片的字幕、比例、封面、時長與音量已檢查；歌曲由使用者試聽，圖片逐張檢查。
- [ ] 章節與成片對時，未使用的佔位文字及區塊已刪除。
- [ ] 已核對平台當下的上傳規格、字數、hashtag 與 AI 揭露設定。
- [ ] 公開貼文中沒有私人檔案路徑、完整提示詞或其他未打算公開的資料。
